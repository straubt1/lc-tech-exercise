Platform Architecture

Self-hosted LangSmith on a dedicated GKE cluster.

Conceptual design for technical review. No infrastructure code. The picture is assets/langsmith-deployment.png. The scene is assets/langsmith-deployment.excalidraw. Walk it on the component slide.

Platform

What we designed around

  • A dedicated GKE Standard cluster.
  • Agents stay where they are and send traces to LangSmith.
  • Durable data sits in managed services, outside the cluster.
  • A standard install now. Hosted agents come later.
Staff sign in with OIDC. Agents use API keys. The API key salt is set once and is not rotated. Observability, evaluation, prompts, and Chat are in. Insights stays off, because that path still expects ClickHouse. LangSmith Deployment, KEDA, and agent servers are a later phase and are not sized here.

Architecture

General pool runs the interface, the APIs, ingest, the playground, the eval runtime, and Chat. SmithDB cache nodes use local SSD. That disk is a cache and is rebuilt from the SmithDB GCS bucket. It is not the durable copy. Point at the diagram while you say this. In the cluster: Envoy is the only door, stateless services share the general pool, and SmithDB has its own cache and compute pools. Beside the cluster: two Cloud SQL instances and Memorystore on private addresses, plus two GCS buckets. SmithDB requires its own single-region bucket in us-west2 for traces and feedback. The blob bucket is multi-region. Pods use Workload Identity. Nodes reach Cloud Storage through Private Google Access.

Application

A dedicated GKE Standard cluster.

Storage

  • Cloud SQL - Users, projects, datasets, experiments, and Chat.
  • Blob GCS bucket - Payloads and attachments.
  • Redis - Ingest queue, cache, and Chat.
  • SmithDB Cloud SQL - Metastore, empty and separate.
  • SmithDB GCS bucket - Traces and feedback.
Three node pools. General runs the interface, the APIs, ingest, the playground, the eval runtime, and Chat. The SmithDB cache pool accepts writes and serves reads. Its local SSD is a cache. The SmithDB compute pool runs compaction and coordination. Both Cloud SQL instances are PostgreSQL 18 with regional high availability. The platform database also holds organizations and API keys. SmithDB requires an empty metastore on its own instance, because that catalog records where trace data was written. Memorystore is Standard high availability and also holds Chat's queue. SmithDB requires a GCS bucket. It is single-region in us-west2, holds the durable copy of traces and feedback, and has no lifecycle expiry. Compaction applies retention. The blob GCS bucket is multi-region us. Short-lived objects expire at 14 days and long-lived objects at 400 days. Recovery from a lost region is a restore in us-west2.

Scaling

The size we start at

About 20 concurrent users and 100 traces a second, with bursts toward 1,000

The size we move to

About 50 concurrent users and 1,000 traces a second, when the first ranges stay full.

  • Redis - Grows with users.
  • Blob GCS bucket - Grows with payloads.
  • SmithDB Cloud SQL - A larger metastore.
  • SmithDB Cache and compute - Larger machines.
  • SmithDB GCS bucket - Grows with retained traces.
Stateless pods scale at 50 percent CPU or 80 percent memory. Queue workers also scale when Redis has a backlog. SmithDB moves from the medium configuration to the large one. Ingest, query, and compaction scale on their own, up to 10. The scheduler and the cluster manager stay at one replica, on a larger machine. Cache nodes go from n2-standard-32 to n2-standard-64. Compute nodes go from n2-standard-8 to n2-standard-16. The SmithDB metastore goes from 6 vCPU and 32 GB to 10 vCPU and 64 GB. Platform Cloud SQL stays at 2 vCPU and 8 GB. Its disk may grow. Memorystore goes from 13 GB to 26 GB. Published guidance wants more backend replicas than this first size allows. Sitting on that cap is the signal to move up.

Agent Development:
Terraform Module Review

A module review that stops before it opens a pull request.

The domain is publishing a Terraform module. The slowdown is a README, a changelog, or a security finding that does not match the code. Default repo is straubt1/terraform-aws-object-storage. The picture is assets/module-review-v4.png. The scene is assets/module-review-v4.excalidraw.

Agents

What Was Built

  • The work is a Terraform module that is ready to publish.
  • Interface, security, and release read the repo in parallel.
  • Recommend drafts the files and the pull request.
  • A person answers yes or no before a Pull Request is created.
Interface compares generated Terraform docs with the README. Security runs Trivy and keeps HIGH and CRITICAL. Release reads the latest tag and the diff, then names the next version. Recommend edits at most ten of the files those findings named. Check has no model. A missing ref ends the run.

Agent Architecture

Point at the diagram. Three specialists, one writer, and a LangGraph interrupt. Tools fetch the repo. Models return a status and findings. Every publish waits on a person. Recommend stops at ten files. Only a yes opens the pull request. Specialists do not edit files. If the diff is empty, release skips the model and says there is nothing to ship. GH_TOKEN is read from the environment. It is not a tool argument, not in a prompt, and not on graph state. The live compare redacts it before the span is stored.

Business Value

Self-service

The module docs are how teams learn to build infrastructure.


Clear module interfaces are what let that scale.


Mistakes in the module docs become tickets on the next release.

The right bump

Major, minor, and patch are applied consistently


Every candidate gets the same recommendation from the org rule, before the tag.

Flexibility and Scale

Recommendations can expand and improve over time.


Consistent recommendations across a large organization.


Human in the Loop gives teams a chance to engage with the recommendation.

Two outcomes. Catch problems while the release is still in development, and leave a module that is easier to use.

Self-service is the point of the catalog. A missing description, a README that drifted, or a setting that is hard to use becomes a ticket. The interface check is the usage recommendation. Recommend writes the file. The person decides whether it ships.

The bump is the contract consumers plan around. The release agent does not invent a scheme. A breaking change is major. A new optional variable or output is minor. Anything else is a patch. Applying that on every ref is how the recommendation stays consistent once there are more modules than reviewers.

KPIs, as directions. This exercise has no production baseline. The evals measure whether status, bump, and finding files are right. These are what that accuracy is for.

  • Adoption time. Consumers spend less time decoding the module.
  • Bump accuracy. Share of tags that match the org rule.
  • Escaped defects. Interface, security, and changelog misses found on the candidate ref, before the tag.
  • Review capacity. Specialists run in parallel. A person only says yes or no.

After launch, write that yes or no back onto the trace. A yes on a ready release is the good case. A no when the release is not ready is also a good case. A tagged module that still misses is the number to drive down.

Friction

Lessons Learned

  • The eval stops at the human gate so the pull request is never scored.
  • Agent development mistakes cost tokens and time.
  • Starting with Evaluations and Experiments would have been better.
The gate came up because interrupt returns before GitHub is called, and the experiment does not resume. The strict bar is intentional, and it makes a one-row prompt regression loud.

Friction

What we would ask for

  • Ability to set max tokens and interrupt.
  • Automatically stop tool calls when you get the same result twice (same input).
  • Template syntax for User Prompts.
Median tokens and latency per named node are printed from the experiment runs today. Asking for that on the experiment page is the product request. Tool trajectory and a changelog-heading score are the next evaluators. A model can name the right version without reading the diff, and the current scores still pass. A token is stripped with a hand-written span on the live compare. Keep the tone to a log of what would have saved time.
